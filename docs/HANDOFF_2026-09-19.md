## Why Phase 1 is not accepted yet

### 1. Identity discovery is too permissive

The capitalized-phrase scan promoted obvious non-person phrases such as `Risk Fresh Phase`, `Slight Delay Bakery`, `Not Nadia Öberg`, and `This So` into people. That can create false `MENTIONED` relationships and excessive deletion collateral.

The next implementation pass must:

1. seed identities from deterministic roster, attendee, speaker, sender, and email sources,
2. treat free-text matches as candidates rather than automatically deletion-relevant people,
3. store only reviewed/high-confidence mappings,
4. leave ambiguous aliases unresolved,
5. rerun and manually inspect the people/alias/evidence-person report.

### 2. Real embeddings are missing

The mock embedding path is tested, but no local `.env` or Google API configuration was present. Before semantic retrieval begins:

1. create a local root `.env` from `.env.example`,
2. set `GOOGLE_API_KEY`, `GEMINI_MODEL`, and `GEMINI_EMBEDDING_MODEL`,
3. keep `.env` uncommitted,
4. run one real embedding smoke test,
5. generate and verify embedding rows for the intended corpus,
6. report any partial failures rather than hiding them.
